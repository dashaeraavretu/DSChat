# DSChat v1 功能对齐清单

基线：`deepseek-ai/chat-demo` v0.1.1（提交副本）。目标：Electron 桌面版 v1 完整复刻官方 demo 的用户可见功能，并保持原有 API 协议。本文逐项给出桌面版预期行为、验证步骤和 v1 状态，并明确区分客户端实现与 DeepSeek API 服务端能力。

## 状态与标记

| 标记 | 含义 |
| --- | --- |
| 复刻 | 客户端行为与官方 demo 对齐，桌面壳不改变交互 |
| 复刻（API 依赖） | 客户端已实现；效果取决于 API 服务是否支持对应扩展/模型能力 |
| 复刻（桌面适配） | 网页版没有、桌面版必须实现的能力（密钥加密、窗口集成等） |
| 未复刻 | 与上游不一致或尚未完成，列入文末缺口 |

所有官方功能在 v1 中的目标状态均为“复刻”。本文编写时，桌面壳和打包配置由并行工作流落地；构建产物验收以 `tests/smoke.mjs` 和 [QA-CHECKLIST.md](QA-CHECKLIST.md) 为准。

## 服务端能力总表

以下能力不是纯前端功能。客户端保留官方 demo 的请求格式和界面，但服务端必须实现相应协议，否则功能会失败或退化。

| 能力 | 客户端职责 | 需要的服务端能力 | 不满足时的表现 |
| --- | --- | --- | --- |
| 智能搜索 | 声明 `deepseek_web_search` 工具；渲染搜索步骤、结果和来源 | 执行联网搜索，返回 `server_tool_use` / `web_search_tool_result`、`deep_search` 等 | 无搜索步骤；可能只按普通聊天回答，或请求报错 |
| 链接阅读 | 始终声明 `deepseek_read_url`；展示阅读步骤；回传 `READ_LINK` 签名 | 抓取网页并把加密页面签名返回；多轮请求时解密恢复上下文 | 阅读失败（`url_not_accessible` / `url_not_allowed` / `unavailable`） |
| 来源引用 | 解析 `citations_delta`，在正文渲染 `[citation:N]` 角标和来源面板 | 在文本块上返回 `web_search_result_location` 引用 | 无角标/来源面板；正文正常 |
| 语音输入 ASR | 录音为 16 kHz 单声道 WAV，`POST /v1/tools/asr` | 转写接口，支持 WAV/Ogg Opus、≤120 秒、≤8 MiB | 提示“语音识别失败” |
| 回复朗读 TTS | `POST /v1/tools/tts`，流式播放 24 kHz PCM | 合成接口，支持 `stella` / `tide` 音色与 PCM 输出 | 提示“暂时无法朗读”或朗读失败 |
| 安全过滤 | 固定发送 `safety_check.level = "high"`；按 `refusal` 丢弃正文/思考 | 内容审核并返回 `stop_reason: refusal`、模板文案 | 无拒绝行为；服务端错误按普通错误展示 |
| 自动标题 | 标题为空时发送 `title: { enabled: true }`；读取 `message_delta.delta.title` | 生成标题扩展 | 会话标题保持“新对话”，可手动重命名 |
| 继续生成 | 以末尾 assistant 前缀续写，构造历史与 `latest_reminder` | 支持 assistant prefill / 续写语义 | 续写可能报错或重复内容；界面按钮仍受客户端条件限制 |
| 深度思考 | 发送 `thinking.enabled`；渲染 thinking 块和签名 | 返回思考增量与签名 | 无思考块；普通回答仍可用 |
| 附件 | Files API 上传，图片用 `image` 块、其余用 `document` 块 | `/anthropic/v1/files`、版面解析、`rich_layout_recognition` / `user_data` | 上传失败、解析失败或配额错误 |
| 位置/时间提示 | 构造 `latest_reminder` 角色消息 | Chat Engine 扩展角色支持 | 请求可能失败；搜索地域性可能下降 |
| 消息模型 | 以 Anthropic 兼容 Messages API 流式请求 `deepseek-flash` | `/anthropic/v1/messages`、SSE 事件格式 | 聊天不可用 |

官方默认 API 地址为 `https://api.deepseek.com`。自建兼容服务必须实现上表能力；仅实现普通 Messages API 时，DSChat 仍可聊天，但搜索、阅读、语音、标题等会降级。

## 1. 会话管理

### F01 多会话

**桌面版预期行为**

- 左侧会话列表支持新建、切换、重命名、删除；移动布局使用抽屉。
- 每个会话独立保存消息树、草稿和附件引用；切换会话不互相污染。
- 会话持久化在 IndexedDB。桌面版通过 `dsc://app` 安全协议加载，IndexedDB/localStorage 按应用源隔离并持久化。
- 列表按更新时间排序，并按“今天 / 昨天 / 7 天 / 30 天”分组；更早的会话按原始 `YYYY-MM` 月份分组。重命名和自动标题不会改变排序。当前会话高亮。
- 会话列表加载失败、会话详情加载失败、保存失败分别有提示和重试入口；保存失败时提示关闭前重试。
- 每个会话独立维护生成状态：同一会话同时只有一个生成，切换会话不会中断其他会话的生成。

**验证步骤**

1. 新建 3 个会话，各发送一条不同内容的消息。
2. 在三个会话间切换，确认消息、草稿、附件和滚动位置不串。
3. 关闭并重启桌面应用，确认会话与分组仍在。
4. 断开网络或模拟 IndexedDB 故障，确认出现加载/保存失败提示和重试按钮。
5. 生成回复时切换到另一个会话，再切回，确认回复仍在生成或已完成。

**v1 状态：复刻。** 客户端逻辑来自上游；桌面协议保证存储源稳定。

### F02 自动标题

**桌面版预期行为**

- 新会话标题初始为“新对话 / New chat”。
- 会话尚无标题时，请求附带 `title: { enabled: true }`；服务端在 `message_delta` 返回 `title` 后写入会话标题。
- 生成过程中手动重命名会取消本轮自动标题写入，迟到的自动标题不会覆盖手动标题。
- 标题成功后不再请求；若服务始终不返回标题，后续轮次仍可能再次请求。服务不支持标题扩展时保持“新对话”，重命名仍可用。

**验证步骤**

1. 新建会话并发送“用一句话解释量子纠缠”。
2. 等待回答完成，确认侧栏出现概括性标题，而不是“新对话”。
3. 再建一个会话，在生成过程中立即重命名为“手动标题”，回答结束后确认标题未被覆盖。
4. 使用不支持 `title` 的兼容服务重复步骤 1，确认不报错且标题保持默认。

**v1 状态：复刻（API 依赖）。** 标题生成本身是服务端能力。

### F03 重命名与删除

**桌面版预期行为**

- 会话菜单提供重命名；失焦/回车提交，列表与持久化同步。
- 删除前弹出确认；确认后删除会话、本地附件原件和草稿引用（仅当没有其他会话引用该原件）。
- 删除当前会话后回到新对话欢迎页（不自动选中相邻会话）。
- 删除失败时保留原会话并提示重试；生成中的会话删除会先停止生成。
- 已上传到 API 服务的文件不会因本地删除会话而删除（上游行为，避免误删共享文件）。

**验证步骤**

1. 右键/更多菜单重命名会话，刷新或重启后确认名称保留。
2. 删除一个有附件的会话，确认确认弹窗文案、删除结果和侧栏更新。
3. 在生成中删除当前会话，确认生成停止、无残留流式状态。
4. 模拟数据库删除失败（如只读存储），确认会话仍在且有错误提示。

**v1 状态：复刻。**

## 2. 消息编辑、重新生成与分支

### F04 编辑提问

**桌面版预期行为**

- 用户消息菜单提供“编辑消息”；进入编辑态后可修改文字并提交。
- 提交后在同一父节点下创建新的用户消息版本和一条新回答，原提问、原回答及后续对话保留为旧分支。
- 编辑后的提问沿用原消息的附件；仅附件、无文字时也允许提交（原消息有附件）。
- 生成中、历史导入中、会话删除中禁止编辑。
- 编辑请求的上下文只包含编辑点之前的当前分支。

**验证步骤**

1. 发送一条消息并等待回答。
2. 编辑该提问，修改措辞后提交。
3. 确认新回答生成；用消息版本切换回到旧提问，确认旧回答和后续对话仍存在。
4. 带图片附件编辑提问，确认附件仍显示并参与新请求。
5. 在生成过程中尝试编辑，确认入口被禁用。

**v1 状态：复刻。**

### F05 重新生成

**桌面版预期行为**

- 回答菜单提供“重新生成”；对指定回答在其原提问下追加新的回答版本。
- 旧回答和其后的对话不被覆盖；切换版本即可回到旧分支。
- 生成中、导入中禁止重新生成。
- 使用当前模型与开关；历史上下文截止到该提问之前。
- 若重新生成失败，新版本标记错误，可再次重新生成。

**验证步骤**

1. 对一条回答点击重新生成，确认出现新的流式回答。
2. 切换回答版本，确认两版内容独立，后续对话随版本恢复。
3. 断网后重新生成，确认错误提示且旧版本仍可用。
4. 生成期间确认重新生成按钮禁用。

**v1 状态：复刻。**

### F06 消息分支/版本切换

**桌面版预期行为**

- 同一父节点下的多条提问或回答形成版本组；界面显示“消息版本 / Message versions”、上一版/下一版。
- 消息树以 `id` / `parentId` / `selectedChildId` 保存；展示和请求上下文统一读取当前选中路径。
- 切换版本只允许当前可见路径上的节点；切换后恢复该版本已选择的后续分支。
- 导入历史时按 `current_message_id` 恢复当前分支；其他节点默认选中最大 ID 的子消息。

**验证步骤**

1. 对同一提问编辑两次、重新生成两次，形成多组版本。
2. 用上一版/下一版在各组间切换，确认正文、来源、附件、后续对话一起切换。
3. 在中间节点切换版本，确认其后分支跟随变化。
4. 导出再导入，确认当前分支和版本数量保持。

**v1 状态：复刻。**

## 3. 生成与推理

### F07 流式回答

**桌面版预期行为**

- 通过 SSE 消费 `message_start`、`content_block_*`、`message_delta`、`message_stop`。
- 正文、思考、工具调用逐步渲染；使用动画帧节流，长回答不阻塞输入。
- 回答期间滚动跟随；用户主动上滚后不强制拉回。
- 支持停止、错误、断流、协议异常分类；`ping` 与未知事件被忽略。
- 生成中在页面隐藏/离开时落盘，完成、停止或失败时最终落盘；正常刷新/重启保留已接收内容，进程被强杀可能丢失最后片段。
- 错误按无效 Key、余额不足、限流、服务繁忙、网络错误分别提示。

**验证步骤**

1. 发送长回答请求，观察逐段渲染与自动滚动。
2. 回答中向上滚动，确认不被拉回底部。
3. 中途断网，确认显示网络/中断错误；重启后已生成部分仍在。
4. 使用无效 Key、低余额、限流场景分别验证提示与操作入口。
5. 检查非 SSE 响应或异常事件不会导致白屏。

**v1 状态：复刻。**

### F08 深度思考

**桌面版预期行为**

- 输入区“DeepThink”开关控制请求的 `thinking.enabled`，默认关闭，状态持久化。
- 开启后展示思考块、思考用时（至少 1 秒）和“已停止”状态；思考可折叠/展开。
- 历史轮次的思考不回传；续写时保留本轮非空思考及其签名。
- 关闭开关后请求 `thinking.disabled`，不展示思考块。
- 安全拒绝时客户端丢弃已下发的思考和正文，只保留允许展示的工具块。

**验证步骤**

1. 打开 DeepThink，问一道需要推理的题，确认思考块流式出现并有用时。
2. 停止生成，确认思考块收尾并标记“已停止”。
3. 关闭 DeepThink 再提问，确认无思考块。
4. 开启思考后停止并继续生成，确认续写保留本轮思考上下文。
5. 使用不支持思考的服务端，确认降级为普通回答或明确错误，不崩溃。

**v1 状态：复刻（API 依赖）。** 思考内容与签名由模型/服务返回。

### F26 安全过滤与拒绝

**桌面版预期行为**

- 所有聊天请求固定携带 `safety_check: { level: "high" }`，并处于扩展模式。
- 服务端返回 `stop_reason: "refusal"` 时，客户端丢弃已下发的思考和普通正文，只展示拒绝模板；“内容由 AI 生成”提示仍在。
- 拒绝回复不能重新生成、不能继续生成、不能朗读，也不进入后续请求上下文。
- 模板/拒绝文案单独展示，不混入工具步骤前的说明文字；导入历史中的模板按原文保留。
- 错误与模板回复仍保留在消息树中，但该轮次不参与上下文。

**验证步骤**

1. 构造一个会触发内容审核的提问，确认显示拒绝模板且不显示部分正文/思考。
2. 确认拒绝回复没有“重新生成”“继续”“朗读”入口。
3. 在拒绝后继续提问，确认拒绝轮次没有进入上下文（开发模式检查请求 messages）。
4. 导入含拒绝模板的历史，确认文案保留且样式正确。
5. 使用不支持 `safety_check` 的服务端，确认普通回答仍可用或返回明确错误。

**v1 状态：复刻（API 依赖）。** 安全审核与拒绝判定完全由服务端执行。

### F12 停止生成

**桌面版预期行为**

- 生成中显示停止按钮；点击后中止当前会话的 SSE 请求，保留已接收的正文/思考/工具状态。
- 停止后回复状态为“已停止”；满足条件时显示“继续”。
- 各会话的生成相互独立，切换会话不会停止原会话的生成；删除会话会先停止该会话的生成；导入历史或删除全部对话会停止所有生成。
- 停止也会中止朗读；排队中的附件上传按现有任务状态处理。

**验证步骤**

1. 生成中点击停止，确认立即停止且内容保留。
2. 停止后检查按钮变为“继续”（仅条件满足时）。
3. 生成中切换会话，确认原会话继续生成；删除该会话或导入历史，确认生成停止且无后台写入错误。
4. 停止后重启应用，确认“已停止”状态和内容持久化。

**v1 状态：复刻。**

### F13 继续生成

**桌面版预期行为**

- 仅最后一条回答可继续；前置条件：`prefix` 为真、状态为已停止或达到 `max_tokens`、非拒绝、非 `tool_use`、不含服务端工具块或模板提示、非导入历史。
- 继续时复用原消息，不新建版本；新流内容追加到已有块之后。
- 沿用原回复的模型、思考/搜索开关与 `latest_reminder`；历史截止到该提问之前，末尾带 assistant 前缀。
- 没有有效正文或非空思考时不发送空 prefill，避免服务端拒绝。

**验证步骤**

1. 生成中停止，点击“继续”，确认内容追加到同一消息。
2. 让回答达到输出上限，确认可继续。
3. 对含搜索结果或链接阅读工具块的回答确认无“继续”按钮。
4. 对拒绝、模板提示、导入历史的回答确认不可继续。
5. 测试空正文/仅思考的停止回复，确认继续时不报空 prefill 错误。

**v1 状态：复刻（API 依赖）。** 服务端需支持末尾 assistant 续写语义。

## 4. 联网能力

### F09 智能搜索

**桌面版预期行为**

- 输入区“Search”开关控制是否声明 `deepseek_web_search`；默认关闭并持久化。
- 开启后服务端可执行文字搜索、边想边搜、图搜；界面展示“正在搜索”、搜索词、找到的网页数、失败/无结果状态。
- 搜索结果以来源卡片/面板展示；点击搜索步骤或结果摘要打开右侧来源面板（窄屏全屏），搜索状态随会话持久化，导入导出保留可展示状态。
- 搜索工具块和历史搜索结果不回传上下文；本轮含搜索工具的回答不能继续。
- 关闭开关后普通聊天不触发搜索，但链接阅读仍启用。

**验证步骤**

1. 打开 Search，提问“今天的科技新闻”，确认出现搜索步骤与来源。
2. 点击搜索步骤或结果摘要打开来源面板，确认标题、站点、摘要/链接；切换会话后面板关闭。
3. 提问一个无结果或让搜索失败的问题，确认状态文案。
4. 关闭 Search 再问同类问题，确认无搜索步骤。
5. 切换会话，确认搜索面板关闭，搜索状态不串会话。

**v1 状态：复刻（API 依赖）。** 联网搜索完全由服务端执行。

### F10 链接阅读

**桌面版预期行为**

- 链接阅读始终启用，请求始终声明 `deepseek_read_url`。
- 用户提问含 HTTP/HTTPS URL 时，服务端可阅读页面；界面展示“阅读”、页内查找、失败状态。

## 8. 桌面版适配

### F24 API Key 加密存储

**桌面版预期行为**

- 每个用户使用自己的 Key；首次无 Key 自动打开设置，校验通过才保存。
- Key 由主进程校验并保存；渲染进程只看到布尔值 `hasApiKey`，不接触明文。
- Key 优先用 Electron `safeStorage` 加密后写入 `userData/secrets.json`（Windows DPAPI）；文件采用临时文件 + rename。
- `safeStorage` 不可用时 Key 只保留在主进程内存，设置页显示“未加密/降级”，重启后需重新输入；不写明文文件，也不回退 `localStorage`。
- 设置页提供“清除 API Key”：确认后通过桥接删除文件、清空主进程内存并清理旧 localStorage 键；重启自动加载解密后的 Key。
- 所有需要鉴权的请求（Messages、Files、ASR、TTS、模型校验）由主进程代理发出；渲染层不能直连上游或指定任意 URL。
- 网页版仍使用 `localStorage` 的 `chat-demo:api-key`；桌面端迁移旧键成功后删除。
- Key 不进入历史导出、日志、构建产物。

**验证步骤**

1. 首次启动输入无效 Key，确认校验失败且不落盘。
2. 输入有效 Key，确认 `secrets.json` 的 `encrypted: true` 且无明文。
3. 重启确认无需重输；通过桥接清除后文件消失。
4. 确认渲染进程无法读取 `apiKey`，`localStorage` 中没有桌面端 Key。
5. 模拟加密不可用（开发构建打桩），确认 Key 仅在主进程内存、设置页显示“未加密/降级”，且不写明文。
6. 网页版写入旧键后启动桌面版，确认迁移并删除 localStorage 旧键。
7. 运行 `pnpm test:proxy`，确认代理对 mock 上游的校验、流式、停止、附件、ASR/TTS 正常。

**v1 状态：复刻（桌面适配）。**

### F25 桌面窗口与安全集成

**桌面版预期行为**

- 使用 `dsc://app` 自定义协议加载 `dist/`：`standard`、`secure`、支持 fetch/CORS/stream，使 IndexedDB、localStorage、WebCrypto、getUserMedia 正常工作。
- 开发模式 `DSCHAT_DEV=1` 加载 `http://localhost:8090`。
- `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；preload 只暴露白名单桥接。
- `dsc://app` 的 HTML 响应带严格 CSP：`script-src 'self'`（禁内联脚本）、`connect-src 'self'`（渲染层不直连 API）、`object-src 'none'`、`base-uri 'none'`；`style-src` 额外允许内联样式以支持 KaTeX/Mermaid。
- Messages、Files、ASR、TTS 与模型校验经主进程代理发出；Key 不进入渲染进程，代理目标只能来自构建期 provider 白名单。
- 外部链接通过系统浏览器打开；应用内禁止任意外部导航和 `<webview>`。附件/图片原件的同源 `blob:` 预览使用同 partition、无 preload、`sandbox`/`contextIsolation` 的受控预览子窗口；子窗口只允许停留在初始 `blob:`，外部导航、重定向与新窗口全部拦截；`data:` URL 不放行。父级 localStorage 隔离未在 0.1.3 实现，defer 到 v1.1。
- 只放行受信任页面的音频权限；摄像头及 `audio+video` 组合请求一律拒绝。
- 单实例锁；生产包禁用 DevTools；窗口最小尺寸 900×620；应用标题 DSChat。
- 支持 `--smoke` 启动检查。

**验证步骤**

1. 打包版启动后检查地址为 `dsc://app/index.html`，存储、麦克风、图表均正常。
2. 在控制台确认 `require` / `process` 不可用。
3. 点击正文链接和来源链接，确认系统浏览器打开。
4. 尝试打开 http(s) 外部链接，确认交给系统浏览器；确认同源 `blob:` 附件预览可用，`data:` 与 `javascript:` URL 被拒绝；在预览子窗口内尝试跳转或打开新窗口，确认被拦截且 URL 仍为初始 `blob:`。
5. 分别请求麦克风、摄像头与 `audio+video` 组合：仅麦克风可用，后两者被拒绝。
6. 启动第二个实例，确认聚焦已有窗口。
7. 生产包确认 DevTools 不可用。

## 复刻缺口与已知限制

以下问题不代表官方 demo 功能缺失，但会影响 v1 验收或桌面体验，发布前需逐项确认：

1. **服务端扩展依赖**：智能搜索、链接阅读、ASR/TTS、安全过滤、自动标题、继续生成、`latest_reminder` 均需 DeepSeek 官方或兼容服务支持。仅替换普通 OpenAI 风格接口不足以实现这些功能。
2. **`document` 块兼容性**：应用始终开启扩展模式（`safety_check: high`、`deepseek_read_url`），而类型注释指出扩展模式可能不支持非图片 `document` 块并返回 400。PDF/Office/文本附件必须在目标服务上单独验收。
3. **`dsc://app` CORS 已不再是阻断项**：桌面版的 Messages、Files、ASR、TTS 与模型校验全部由主进程代理发出，不依赖渲染层的 CORS。自建网关只需在构建时设置 `DSCHAT_API_ORIGIN`；构建脚本会把结果写入 `electron/provider-config.json`，主进程用同一份配置作为默认 provider 与代理白名单。网页版仍需服务端允许相应 CORS。
4. **本地附件打开（v1 已处理）**：已发送的附件/图片原件通过 `window.open(blob:…)` 打开；主进程仅对同源 `blob:` 放行受控预览子窗口（同 partition、无 preload、`sandbox`/`contextIsolation`），子窗口导航、重定向与新窗口均被拦截；`data:` 不放行，`http/https` 仍交给系统浏览器。`pnpm smoke:blob` 与真实 PNG/PDF 预览实测通过。预览与主窗口同源，父级 localStorage 隔离 defer 到 v1.1。
5. **密钥生命周期**：Key 只由主进程持有；`safeStorage` 可用时加密落盘，不可用时仅保留在主进程内存并在设置页显示“未加密/降级”，不写明文、不回退 localStorage。设置页提供“清除 API Key”。启动时仍未主动校验 Key，首次请求失败后按原有错误提示处理。
6. **网页版与桌面版数据不互通**：`localhost:8090`、`dsc://app` 和 `file://` 是不同存储源，会话/附件不会自动迁移；只有 API Key 有迁移逻辑。历史需通过 ZIP 导入导出。
7. **远端文件生命周期**：`deleteFile` 从未调用；删除会话、移除附件或删除全部对话都不会删除已上传到 API 服务的文件，可能累积占用配额，且删除确认文案与实际行为不一致。
8. **历史与流式提示的边界**：只支持版本 3、ZIP32、STORE/DEFLATE、非加密单卷；导入后引用、模型、思考签名、结构化错误、`latestReminder` 等不保留，回复不能继续。导入失败界面统一显示通用错误，不区分具体原因；空消息的流中断错误可能没有可见提示。
9. **移动布局不可达**：响应式布局已实现，但 Electron 窗口最小宽度 900 px，正常桌面窗口无法触达 `<768px` 断点，只能在开发模式设备模拟中验证。
10. **提示文案差异**：拖拽遮罩写“最多 50 个、每个 64 MB”，但 `user_data` 类文件实际上限 32 MB；月份分组显示原始 `YYYY-MM`。
11. **朗读与语音依赖服务端**：ASR/TTS 不可用时输入和朗读入口会报错；桌面版不做本地识别或本地语音合成。
12. **自动更新与签名**：未包含自动更新；未签名安装包会触发 SmartScreen。代码签名与更新源属于发布配置，不在功能复刻范围内。
13. **包元数据**：`package.json` 的 `name` 已统一为 `dschat`，`description` 与 `productName` 均为 DSChat；发布前仍建议核对安装包属性中的 ProductName/FileVersion。
14. **README**：`README.md` 为中文默认版（面向用户），`README.en.md` 为英文版；内部功能/验收细节见 `docs/` 下的文档。
15. **并行开发影响**：`src/`、`electron/`、`package.json` 由其他工作流修改，本文基于编写时可见实现；最终验收需以完整构建和 `node tests/smoke.mjs`、`pnpm type`、`pnpm lint` 为准。
